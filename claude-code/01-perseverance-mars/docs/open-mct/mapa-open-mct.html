Open MCT 4.3.1
    nasa/openmct · guía para la fase de integración

    Cómo funciona Open MCT

    Open MCT es un framework web de NASA para construir paneles de telemetría. Esta guía reúne la revisión de arquitectura y la revisión del código, pensada para conectar la simulación del rover Perseverance (Vite + Three.js) como fuente de datos en vivo.

    Resumen

    4.3.1versión revisada
    Apache-2.0licencia
    Vue 3.4.24UI, incluido en el bundle
    ~600 .jsen src/, 261 .vue
    126archivos *Spec.js

    Open MCT no dibuja datos por sí solo: tú le dices qué objetos existen (object provider), cómo se agrupan (composition) y de dónde salen sus valores (telemetry provider). Con eso, sus vistas (plots, tablas, gauges, layouts) y el Time Conductor funcionan sobre tus datos.

    Lo esencial para integrarlo
    • Se consume como un bundle UMD ya compilado (dist/openmct.js), no como fuentes ESM. Crea una instancia única por página.
    • Necesita servir archivos estáticos aparte: workers, el CSS del tema, fuentes e imágenes (openmct.setAssetPath()).
    • Plugins mínimos: UTCTimeSystem, un tema, y LocalStorage + MyItems si quieres crear y guardar vistas. Conductor para el modo realtime.
    • Los timestamps deben ser milisegundos Unix cercanos a Date.now(); si no, las vistas salen vacías.
    • El punto de unión con Three.js es un telemetry provider con subscribe() alimentado desde el loop de la simulación.

    Nada de esto se ejecutó: los dos informes se basan en leer el código. La sección “Sin verificar” lista lo que falta comprobar antes de integrar.

    Build y distribución

    • Webpack 5: .webpack/webpack.{common,dev,prod,coverage}.mjs. npm run build = build:prod + npx tsc (genera dist/types). El repo es JavaScript; tsconfig.json solo emite .d.ts.
    • Entradas de webpack: openmct, varios workers (generatorWorker, couchDBChangesFeed, inMemorySearchWorker, compsMathWorker, historicalTelemetryWorker) y tres temas SCSS.
    • La salida es UMD (library: {name: 'openmct', type: 'umd', export: 'default'}): el módulo ya es la instancia MCT.
    • package.json: main y module apuntan a dist/openmct.js. .npmignore excluye src y example, así que el paquete npm trae el dist compilado.
    • Node >=24.14.1 (.nvmrc) solo hace falta para compilar el repo. Consumir el paquete no lo exige. El .npmrc del repo activa engine-strict.
    • npm start levanta el dev server de webpack en el puerto 8080 y solo sirve para desarrollar Open MCT.

    Modelo de datos

    Domain object

    Es un objeto plano con identifier: {namespace, key}, type, name, location y, según el caso, composition: [identifier…] y telemetry: {values: […]}. Su keyString es namespace:key (makeKeyString / parseKeyString).

    Un objeto de un tipo no registrado se trata como unknown, y request/subscribe devuelven vacío para él.

    Providers y raíz

    objects.addProvider(ns, {get(identifier) → Promise<DomainObject>}). Gana el último registrado. create, update y delete son opcionales y los usan los providers de persistencia.

    objects.addRoot(identifier, priority) añade una raíz. El objeto ROOT lo sirve RootObjectProvider.

    Composición

    DefaultCompositionProvider aplica a cualquier objeto con propiedad composition. Un provider propio necesita appliesTo(obj) y load(obj) → Promise<Identifier[]>.

    Persistencia

    LocalStorage(namespace = '', storageSpace = 'mct') en src/plugins/localStorage/, CouchDB(url) en src/plugins/persistence/couch/ y MyItems(name, namespace, priority) para la carpeta mine. Sin persistencia no se pueden crear ni guardar layouts ni plots.

    Flujo de telemetría

    La telemetría pasa por tres piezas: los metadatos que describen cada valor, el request histórico y el subscribe en vivo. Las vistas no llaman a tu provider directamente: lo hacen a través de TelemetryCollection.

    Request histórico y suscripción en vivo
    sequenceDiagram
  participant V as Vista (Plot/Table/Gauge)
  participant TC as TelemetryCollection
  participant T as TelemetryAPI
  participant P as Tu provider
  participant Time as TimeAPI/Conductor
  V->>TC: requestCollection(obj)
  TC->>Time: getBounds(), modo
  TC->>T: request(obj, {start,end,domain,signal})
  T->>P: supportsRequest(obj) y request(obj, opts)
  P-->>T: Promise de datums (historico)
  T-->>TC: datos
  TC->>T: subscribe(obj, cb, {strategy})
  T->>P: supportsSubscribe(obj) y subscribe(obj, cb)
  loop cada dato nuevo
    P-->>T: cb(datum)
    T-->>TC: datum
    TC-->>V: add (si esta dentro de bounds)
  end
  Time-->>TC: tick o cambio de bounds
  TC-->>V: descarta datos fuera de bounds
  V->>T: unsubscribe()
  T->>P: unsubscribe (si no quedan callbacks)

    Metadatos y formatos

    • DefaultMetadataProvider devuelve domainObject.telemetry, así que basta con declarar telemetry.values en tu objeto. TelemetryMetadataManager interpreta key, name, source, format, unit, min, max, enumerations y hints.
    • Los hints domain (eje X) y range (eje Y) mandan en plots y tablas. También existen image, thumbnail e imageDownloadName.
    • Regla crítica: debe haber un value cuyo key coincida con el time system activo ('utc') y con hints.domain. Con source: 'timestamp' puedes mapear tu campo timestamp a la key utc. Si falta, TelemetryCollection avisa con TIMESYSTEM_KEY_WARNING.
    • TelemetryValueFormatter resuelve el formato por value. Soporta enum, string, formatString con sprintf ('%0.2f') y arrays. Formatos propios con telemetry.addFormat({key, format, parse, validate}).

    Providers

    Un mismo objeto provider puede implementar varias capacidades; addProvider lo añade a cada lista con unshift, así que gana el último registrado.

    CapacidadMétodos
    HistóricosupportsRequest(obj), request(obj, options) → Promise<datum[]> ordenado ascendente por dominio.
    Tiempo realsupportsSubscribe(obj), subscribe(obj, callback, options) → función unsubscribe. Llama callback(datum) por cada dato.
    MetadatossupportsMetadata, getMetadata.
    LímitessupportsLimits, getLimitEvaluator (Plot, Table, LAD) o getLimits (Gauge). Ejemplo: example/generator/SinewaveLimitProvider.js.
    Datos obsoletossupportsStaleness, subscribeToStaleness, isStale.

    Request y subscribe en detalle

    • Request: standardizeRequestOptions rellena timeContext, domain, start y end con los bounds del conductor, y añade un signal (AbortController). Estrategias: latest con size (Gauge, LAD) y minmax con size ≈ píxeles (Plot). Sin provider de request, notifica un error y devuelve [].
    • Subscribe: hay una caché por identifier + hash(options), de modo que varias vistas comparten una sola suscripción al provider. Estrategia latest (por defecto) o batch; esta última solo se respeta si el provider implementa supportsBatching.
    • TelemetryCollection (src/api/telemetry/TelemetryCollection.js) pide histórico y suscripción juntos, mantiene los datos ordenados por búsqueda binaria, elimina duplicados, guarda en un futureBuffer lo posterior al end y se recorta con los ticks del reloj. Emite add, remove, clear, requestStarted y requestEnded.
    • Tiempo: en modo realtime LocalClock hace tick cada 100 ms y los bounds son now + clockOffsets. En modo fixed solo hay request.
    • openmct.telemetry.BatchingWebSocket agrupa mensajes de un WebSocket en un worker con reconexión. Para una simulación en el mismo navegador probablemente no hace falta.

    Instalación

    • Opción A (la documentada en API.md): npm i openmct, copiar node_modules/openmct/dist/ a public/openmct/ y cargar /openmct/openmct.js con un <script>. Crea window.openmct y fija la ruta de assets desde document.currentScript.
    • Opción B: import openmct from 'openmct'. No se verificó con Vite. Sin document.currentScript, los assets se piden a getAssetPath() (por defecto '/'), así que hay que llamar openmct.setAssetPath('/openmct/').
    • Assets que se cargan en runtime (relativos al asset path): espressoTheme.css, snowTheme.css o darkmatterTheme.css (sin tema la UI sale sin estilos), inMemorySearchWorker.js (SharedWorker), los workers de comps, telemetría histórica y CouchDB solo si usas esas funciones, y fuentes e iconos de dist/fonts/.

    Plugin del rover

    src/rover-telemetry.js · sin ejecutar
    const NS = 'rover';
const CHANNELS = { speed: 'm/s', pitch: 'deg', roll: 'deg', heading: 'deg' };
const listeners = new Set();
const history = [];

// Llamar desde el loop de Three.js (10-30 Hz)
export function pushRoverState(state) {
  const snapshot = { timestamp: Date.now(), ...state };   // ms Unix
  history.push(snapshot);
  if (history.length > 20000) history.shift();
  listeners.forEach((fn) => fn(snapshot));
}

export function RoverTelemetryPlugin() {
  return function install(openmct) {
    openmct.types.addType('rover.channel', { name: 'Rover Channel', cssClass: 'icon-telemetry' });

    // Objetos: una carpeta raíz y un objeto por canal
    openmct.objects.addRoot({ namespace: NS, key: 'perseverance' }, openmct.priority.HIGH);
    openmct.objects.addProvider(NS, {
      get(id) {
        if (id.key === 'perseverance') {
          return Promise.resolve({
            identifier: id, name: 'Perseverance', type: 'folder', location: 'ROOT',
            composition: Object.keys(CHANNELS).map((key) => ({ namespace: NS, key }))
          });
        }
        return Promise.resolve({
          identifier: id, name: id.key, type: 'rover.channel', location: `${NS}:perseverance`,
          telemetry: { values: [
            { key: 'utc', source: 'timestamp', name: 'Time', format: 'utc', hints: { domain: 1 } },
            { key: 'value', name: id.key, unit: CHANNELS[id.key], format: 'float', hints: { range: 1 } }
          ] }
        });
      }
    });

    // Telemetría: histórico + tiempo real
    const isChannel = (o) => o.type === 'rover.channel';
    const toDatum = (s, key) => ({ timestamp: s.timestamp, value: s[key] });
    openmct.telemetry.addProvider({
      supportsRequest: isChannel,
      request(o, { start, end }) {
        return Promise.resolve(history
          .filter((s) => s.timestamp >= start && s.timestamp <= end)
          .map((s) => toDatum(s, o.identifier.key)));
      },
      supportsSubscribe: isChannel,
      subscribe(o, callback) {
        const fn = (s) => callback(toDatum(s, o.identifier.key));
        listeners.add(fn);
        return () => listeners.delete(fn);
      }
    });
  };
}

    Riesgos al integrar

    TemaQué pasa y qué hacer
    UMD y globalEl paquete npm trae un bundle webpack UMD, no ESM de fuentes. Un solo openmct por página.
    Assets por rutaWorkers y CSS de tema se cargan por URL: ${getAssetPath()}${__OPENMCT_ROOT_RELATIVE__}archivo (prod "", dev "dist/"). Sirve openmct.js, workers, *Theme.css, images/, fonts/, icons/ desde esa raíz.
    TiempoOpen MCT trabaja en ms Unix con el sistema utc. Si tu simulación usa tiempo relativo, conviértelo a Date.now(). Sin UTCTimeSystem no hay reloj local. Con Conductor de una sola opción realtime, la validación lo permite; sin él, llama time.setTimeSystem('utc'), setClock('local') y setMode('realtime', offsets).
    FrecuenciaA 60 Hz el callback latest recibe datos sin agrupar. Reduce a 10-30 Hz, o implementa supportsBatching y usa batch. Los bounds se actualizan cada 100 ms.
    UI y canvasEl layout .l-shell asume ocupar el viewport y el tema trae un reset (normalize-min) y estilos globales. Colócalo en un contenedor aparte, al lado del canvas, o en un iframe (comunicación por BroadcastChannel o postMessage). No lo montes encima del canvas.
    PesoEl bundle incluye Vue 3.4.24 (con compilador de templates), plotly, mathjs, moment, lodash, html2canvas y painterro. Webpack sube maxEntrypointSize a 27 MB. No se midió el tamaño real. No cargues otra copia de Vue en la misma página.
    Workers y CSPSharedWorker exige mismo origen y contexto seguro (https o localhost). El worker de WebSocket se crea desde un Blob. Con CSP, permite worker-src y blob:, y style-src para el tema.
    Sin UIstartHeadless() usa solo la capa de datos y tiempo, pero entonces no hay plots ni tablas.
    Licencia y marcaApache-2.0 con cabecera en cada archivo; hay código de terceros (src/plugins/licenses/third-party-licenses.json). El repo no concede uso del nombre ni del logo de NASA. Es una lectura del informe, no asesoría legal.
